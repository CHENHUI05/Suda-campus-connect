# Linux 版测试结果

测试日期：2026-11-09。由于没有可用的 Linux 环境与校园网服务器，测试在 Windows 本机的 Git Bash（GNU bash 5.3，cygwin）中通过**模拟命令**完成，未在真实 Linux 发行版上运行。

## 测试方式

编写 `ip`、`curl`、`crontab` 三个 mock 命令放入 PATH 最前面，由它们返回预设的网卡信息、网关响应和任务计划行为，驱动脚本执行并断言退出码与输出。

## 已通过的 19 项检查

- 登录流程：连接成功、已在线（ret_code=2）、认证失败、网关不可达（curl 退出码 7）
- 响应解析：紧凑 JSON、带空格 JSON、JSONP 包裹（`dr1002({...})`）
- 网卡选择：自动路由选源地址、指定 IFACE 成功、指定网卡无地址、路由无 src 地址
- 登出流程：网关确认成功、网关返回失败
- 任务计划：start 写入周期与 @reboot 两条 cron、重复 start 幂等不重复、stop 移除全部任务
- 其他：status 状态展示、无参数用法报错、缺少配置文件、空用户名拒绝、网关参数（user_account / wlan_user_ip）透传正确

## 测试中发现并修复的问题

初版脚本在 `set -o pipefail` 下，当网关响应缺少 `ret_code` 字段（登录成功响应即如此）时，字段解析管道返回非零并触发 `set -e`，导致脚本在成功路径上异常退出。已修复解析函数，字段缺失时返回空串且不改变退出码。

## 测试限制（请务必知悉）

- 未在 CentOS、Ubuntu 等真实 Linux 系统上运行，不同发行版自带工具版本（curl、iproute2、cron 实现）的差异未覆盖。
- 未与真实校园网网关交互，登录、登出是否成功以服务器实际运行结果为准。
- `crontab` 为模拟实现，真实环境下 SELinux、PAM、cron 服务未运行等情况无法模拟。
- `curl --data-urlencode` 的特殊字符编码依赖真实 curl 的标准行为，模拟环境未验证编码本身。
- 未测量实际资源占用；脚本设计为每次执行后退出，无常驻进程。

首次在真实服务器部署时，建议先执行 `./suda-campus.sh connect` 手动验证，确认成功后再执行 `start` 写入定时任务。
